- 作成日時: 2026年11月08日 17:37 (JST)
- 対象デバイス: Even Realities G2（Even Hub アプリとして実装）
- 作成者: Claude（調査にもとづく提案。未確定事項は「要確認」と明記）

---

## 0. 結論（先に要点）

1. **実装形態は「Even Hub アプリ」一択**。TypeScript で書いた Web アプリが、スマホの Even アプリ内 WebView で動き、
   SDK（`@evenrealities/even_hub_sdk`、最新 0.0.16）経由でメガネのマイクとディスプレイを使う。
   メガネ本体にコードは載らない。ネイティブ iOS/Android アプリは不要。
2. **マイク音声は SDK から 16kHz / 16bit / モノラル PCM で取れる**。音声認識（STT）も翻訳も SDK には無い。
   → 自分でクラウドの音声認識・翻訳サービスに WebSocket で流す必要がある。
3. **4 パターンの翻訳は、実際には 2 つのルールに集約できる**。
   「日本語が聞こえたら英語を出す」「英語が聞こえたら日本語を出す」。
   誰が話したか（私 / 相手）は、SDK 0.0.14 以降で音声フレームごとに付く `speakerRole`（Self / Other）で判定し、表示ラベルに使う。
4. **最大の設計上の論点は「相手はメガネの表示を見られない」こと**。
   私が日本語で話した → 英語訳は、相手に見せるならスマホ画面に出すか、スマホから音声で読み上げる必要がある。
   メガネに出す意味があるのは、主に「相手の英語 → 日本語」と「自分の発話の確認」。
5. **最初に実機で潰すべきリスク**: サードパーティ製コンテナで**日本語フォントが表示できるか**。
   メガネのフォントは 1 種類固定で、フォントに無い文字は**無言で欠落**する仕様。Even 純正の翻訳機能は日本語を表示できるので
   フォント自体には日本語グリフがある可能性が高いが、SDK 経由で表示できるかは未検証（要確認・最優先）。

## 2. 提案する全体構成

```
[G2 メガネ]  --BLE-->  [スマホ Even アプリ]  --WebView-->  [本アプリ (TS/Vite)]
   マイク4ch                                                      │
   ディスプレイ <---------- SDK (textContainerUpgrade) -----------┤
                                                                  │ WebSocket (PCM 16kHz)
                                                                  ▼
                                                    [音声認識 + 言語判定 + 翻訳 サービス]
                                                                  │ 原文トークン / 訳文トークン
                                                                  ▼
                                               表示ルーティング（メガネ / スマホ画面 / 読み上げ）
```

### 2-1. 音声認識・翻訳エンジンの選択肢

| 案 | 構成 | 長所 | 短所 |
|---|---|---|---|
| **A. Soniox リアルタイム API（推奨 MVP）** | 1 本の WebSocket に PCM を流すだけで、言語自動判定＋文字起こし＋翻訳がトークン単位で返る。日英の**双方向翻訳モード**あり（`translation.type = "two_way"`、要確認） | 実装が最も小さい。遅延が短い。既存 OSS（soniox-translate）が WebView から直結して動作実績あり | 翻訳品質は専用 LLM より素朴になりがち。サービス依存 |
| B. ストリーミング STT（Deepgram / AssemblyAI / Soniox）＋ Claude で翻訳 | 確定した文単位で Claude API に翻訳させる | 文脈を踏まえた自然な訳。固有名詞・敬語の調整などプロンプトで制御できる | 文確定を待つため 1〜2 秒遅くなる。API キーが 2 つ。中継サーバーがほぼ必須 |
| C. OpenAI Realtime / Gemini Live 等の音声対話モデル | 音声を直接入れて訳文を出す | 高品質 | コスト高、WebView から直結しにくい、過剰 |

**推奨**: まず **A** で「動くもの」を作り、翻訳品質に不満が出たら **B（Claude 翻訳）を後段に追加**する二段構え。
コードは「音声入力」「認識・翻訳エンジン」「表示」を分離して、エンジン差し替えを容易にする。

### 2-2. 翻訳方向と話者の扱い

- 翻訳方向は**検出された言語**で決める（話者ではなく）。
  - 検出 = 日本語 → 英語訳を生成
  - 検出 = 英語 → 日本語訳を生成
- `speakerRole`（Self / Other）は**表示ラベル**（「私」「相手」）と、**出力先の振り分け**に使う。
  - 相手の発話 → 訳文をメガネに表示（私が読む）
  - 私の発話 → 訳文をスマホ画面に大きく表示 and/or スマホから読み上げ（相手に向ける）。メガネには原文を小さく出して確認用に
- `speakerRole` が `Unknown`（スマホマイク使用時や旧バージョン）の場合は、言語で代用（例: 私＝日本語話者という設定なら、日本語＝私）。

### 2-3. メガネ画面のレイアウト案（576 × 288）

```
┌──────────────────────────────────────────────┐
│ 相手: Could you send me the quotation by...   │  上段 2 行: 直近の原文（相手 or 私）
├──────────────────────────────────────────────┤
│ 見積書を金曜日までに送っていただけますか？       │
│                                               │  下段 6〜8 行: 訳文（新しいものが下に積まれる）
│ 私: 承知しました、木曜日に送ります              │
│ → Understood, I will send it on Thursday.     │
│                                               │
│ ● REC   JA⇄EN   🔋82%                        │  最下行: 状態
└──────────────────────────────────────────────┘
```

- 中央揃え・サイズ変更が無いので、ラベル（「相手:」「私:」や「→」）で見分ける。
- 更新は 120ms 程度でデバウンスし、`textContainerUpgrade` を 1 本の直列キューで呼ぶ（既存 OSS の実績ある方式）。
- 画面に出す履歴は直近 1,400 文字程度まで、古いものから捨てる。全履歴はスマホ側に保持。

### 2-4. 操作（メガネ側）

| 操作 | 動作 |
|---|---|
| シングルタップ | 認識 開始 / 停止（開始時にマイク ON） |
| 長押し | 原文表示 ⇄ 訳文のみ表示 の切替（案） |
| ダブルタップ | アプリ終了確認（審査要件） |

### 2-5. スマホ側画面（WebView の HTML）

- 会話ログ全文（原文＋訳文、話者ラベル、時刻）
- 「相手に見せる」用の大きな訳文表示（私の発話の英訳）
- 設定: API キー、マイク（メガネ/スマホ）、私の母語、読み上げ ON/OFF、表示モード
- API キーは `bridge.setLocalStorage` に保存（ブラウザの localStorage はアプリ再起動で消える報告があるため不可）

### 2-6. 開発・配布フロー

1. PC に Node.js、`@evenrealities/evenhub-cli` と simulator を導入
2. Vite の開発サーバーを LAN で起動 → `evenhub-cli qr` で QR を出し、Even アプリ（開発者モード）で読み込み
3. 表示・操作はシミュレータで先行確認、マイクは実機でしか試せない
4. 配布: 個人利用なら QR サイドロードで十分。Even Hub 公開するなら `.ehpk` を作り審査へ

## 3. 確認したいこと（回答いただけると設計が確定します）

### 必須

1. **実機と環境**: G2 本体はすでにお手元にありますか。Even アプリのバージョン（SDK 0.0.16 は Even アプリ 2.2.10 以上が必要）、
   スマホは iPhone / Android のどちらですか。開発用 PC は Mac / Windows のどちらで、Node.js は入っていますか。
2. **「私の英訳」を相手にどう届けるか**: 相手はメガネの表示を見られません。
   (a) スマホ画面に大きく表示して相手に見せる、(b) スマホから音声で読み上げる、(c) 両方、(d) まずは自分の確認用にメガネに出すだけでよい、のどれにしますか。
3. **音声認識・翻訳サービス**: 上記 A（Soniox 単体）で始めてよいですか。すでに契約・API キーをお持ちのサービス（Soniox / Deepgram / AssemblyAI / OpenAI / Anthropic / Google）があれば教えてください。
   月々の利用料は発生します（料金は選定後に確認します）。
4. **利用形態**: ご自身用（サイドロード）か、Even Hub で一般公開も視野に入れますか。公開する場合は API キーをアプリに埋め込めないため、小さな中継サーバー（Cloudflare Workers 等）が必要になります。

### あると良い

5. **表示レイアウト**: 上の 2-3 案（原文 上段 ＋ 訳文 下段）でよいか。あるいは「訳文のみ」を基本にしてタップで原文表示に切り替える方が良いですか。
6. **話者判定の方針**: 相手も日本語を話す場面（通訳が要らない場面）では何も表示しなくてよいですか。
   また私が英語で話したときの日本語訳は「自分の確認用」としてメガネに出せばよいですか。
7. **マイク**: 基本はメガネのマイクでよいですか。相手の声が拾いにくい場合に備えて、スマホのマイクに切り替える設定を付けますか。
8. **会話ログ**: スマホ側に会話履歴を保存・エクスポート（テキストコピー / 共有）する機能は要りますか。
9. **用途**: 主な利用シーン（対面商談、会議、旅行、電話越しなど）を教えてください。騒音環境や専門用語の有無で、エンジンの選択とプロンプト設計が変わります。
10. **UI 言語**: スマホ側の設定画面は日本語でよいですか。

## 4. 進め方（案）

| フェーズ | 内容 | 成果物 |
|---|---|---|
| 0 | プロジェクト雛形（Vite + TS + SDK）、シミュレータで画面表示、**実機で日本語フォント表示を確認** | 「こんにちは / Hello」が両方メガネに出る |
